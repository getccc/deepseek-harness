# Agent Note: composer BI 分析 chip 席位

Status: implemented

[English](2026-09-16-composer-bi-analysis-chip-seat.md) | 中文

## 问题

BI 分析是 Team 工作 composer 即将获得的能力：拥有工作区的成员要求对公司数据出一份报告。它需要在 composer 工具行里找到位置，而那里已经有 `+` 启动器、联网开关、录音转写 chip，以及知识与办公 chip；设计把它放在办公右侧。若把这个位置决策塞进那个还要接通数据源并运行分析的改动里，它就会被淹没。

## 决策

`@deepseek-ai/dsh-client-ui-bi` 拥有该 chip。它以 order 120 加入 `conversation.input.left`，位于 110 的办公 chip 之后，并且只在工作会话中渲染——聊天对话没有可供分析的工作区。与[语音席位](2026-09-16-composer-voice-control-seats.zh.md)一样，它已就位但不可用：字形、文案、`aria-disabled`，以及说明该能力尚未构建的工具提示，没有点击处理、没有状态、不读取投影、也不调用 Remote。`ui-primitives` 新增它所用的趋势字形，采用描边而非填充，以便与紧邻的办公「可视化」柱状字形区分开。

挂载它的是 **Team bundle**，就在办公 chip 那一行旁边，而不是语音席位所在的 web-app bundle：这个 chip 的邻居是 Team 独有的，而普通 `dsh web` 部署没有可达的 BI 服务，因此即便能力落地，那里的 chip 背后也依然空无一物。

## 备选方案

**挂载到 web-app bundle。** 语音席位正在那里，而且这样能让该 chip 进入组装随附 web-app 层的 Web 快照通道。否决：本 chip 所对齐的办公 chip 是 Team 独有的，因此在普通 `dsh web` 的工作会话里，这个 chip 会孤零零地对着一个该部署不会拥有的能力。代价是该 chip 没有 Web 基准，这与办公、知识 chip 的现状完全一致；本包自身的规格就是它的覆盖。

**复用 `IconChartOutline16` 作为标记。** 办公选择器已经用它表示「可视化」种类。同样的柱状字形出现两次——一次在办公菜单里、一次在紧邻的 chip 上——会被读成同一件事；一条描边趋势线只是一枚新字形，却能把两者分开。

**等能力可用再一起发布。** 与语音席位相同的论据：这一行的布局可以被单独评审，而能力改动应当关于数据源与分析本身。

## 影响

工作 composer 这一行到 BI 为止已经定型：能力改动只需给一个已经存在的 chip 添加行为，在一个已经存在的包里完成。代价是发布了一个什么都不做的界面——点击除了工具提示之外不会有任何反应，包的「已知限制」对此明说。只有 Team 部署会看到它。

## 测试

本包自身的规格固定了注册及其拆除、仅工作会话的门槛，以及两种语言的文案。没有 Web 基准：快照通道组装的是 web-app，而它不挂载 Team 行，因此这个 chip 和办公、知识 chip 一样处在其之外。
