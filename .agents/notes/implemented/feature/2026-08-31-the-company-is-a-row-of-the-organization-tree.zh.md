# Agent Note：公司是组织树里的一行

Status: implemented

[English](2026-08-31-the-company-is-a-row-of-the-organization-tree.md) | 中文

## 问题

控制台把组织画成部门树的第一行，并标注它是公司，但这一行背后的记录只有一个名称。部门行打开的编辑弹框有八个字段，公司行打开的只有一个。这棵树读起来是一种东西，编辑起来却是两种；而管理员最先看到的那一行，编号、负责人、电话与邮箱四列永远是空的。

同一个页面上还有两个更小的缺陷。控制台的每个弹框都在首次打开之前就已挂载，因此 Ant Design 只读一次 `initialValues`，为第二条记录重新打开的弹框里仍然是上一条记录的值。另外该页面一行只放一个字段、标签压在输入框上方，八个字段的弹框因此比它所在的屏幕还高。

## 决定

`Organization` 携带 `Department` 携带的那组描述字段：编号、负责人、联系电话与邮箱。`setOrganizationName` 由 `updateOrganization` 取代，其部分更新规则就是 `updateDepartment` 已经遵循的那套——未给出的字段保持原样，置为 `null` 的字段被清除。删除账户会清除它担任的公司负责人，正如它已经清除部门负责人一样，因为该列是外键，否则会拒绝这次删除。

SQLite 后端向 `organization` 表添加这四列，并把 `SCHEMA_VERSION` 推进到 4。它们可空且不带默认值，这正是既有的增量路径对“向早期构建已创建的表新增列”的要求。

`PATCH /organization` 在名称之外接受这些字段，`WireOrganization` 连同解析好的负责人显示名一并传出，因此该行不需要第二次请求就能显示公司由谁负责。控制台的页面成为「组织管理」/ Organizations，其名称与编号列成为「组织名称」/「组织编号」：这棵树里既有公司也有部门，上面的字现在就是这么说的。

### 一行两个字段

`FormModal` 接受一个 `columns` 属性。取 `2` 时它加宽弹框、把每个标签放到控件旁边，并将表单项排成网格单元；需要整行的子元素用 `form-grid-wide` 提出要求。组织管理页面传入它；其余页面保持它们各自写就的单列布局。

### 弹框重新打开时对准它被打开的那条记录

`FormModal` 在 `open` 变为真时重置它的表单，这正是把被编辑的记录填进字段的动作。`initialValues` 被刻意排除在该 effect 的依赖之外：调用方在每次渲染时都会重建它，逐次重置会丢掉管理员正在输入的内容。

## 曾考虑的替代方案

**让公司行只能改名，并把原因说出来。** 否决。这一行已经宣称与其下各行相同的列；解释其中七列为何永远为空，比把它们存下来代价更大。

**去掉公司行，让类别为 `company` 的顶级部门充当根。** 否决。组织是部署所配置的那一个，也是每个账户、角色与授权所挂靠的那一个；把它变成一个普通的可编辑树节点，等于允许管理员从一张表格里删掉这个租户。

**为对称起见，也给公司上级、类别与排序。** 否决。它就是根、就是公司，而且只有一个，这三个字段都会成为只有一个合法值的控件。

## 结果

管理员用同一组字段编辑整棵树。存储多了一个 schema 版本，以及删除账户时要清除的第二个负责人列。公司的编号不与部门编号做校验：两者位于不同的表，也没有任何东西把其中之一当作键来读。

控制台没有测试设施，因此弹框行为由其下的 `team-admin-api` 与 `account-store-sqlite` 测试，以及对该页面本身的评审来把关。
