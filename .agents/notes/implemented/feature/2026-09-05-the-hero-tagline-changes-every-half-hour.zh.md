# Agent Note: The hero tagline changes every half hour

Status: implemented

[English](2026-09-05-the-hero-tagline-changes-every-half-hour.md) | 中文

## 问题

[Hero 问候跟随一天中的时段](2026-09-02-the-hero-greeting-follows-the-part-of-the-day.zh.md)给了空白会话标题七个时段，每个时段一句问候、一句寄语，因此成员整个下午——足足四个半小时——看到的是同一句寄语，而问候从不说明是谁在说话。产品的文案表现在在每句问候里点出说话者——助手小微——并给一天中的每个半小时各配一句寄语：四十八句随着天光走过一天，从午夜的 `夜色归于宁静` 到 23:30 的 `临近子夜时分`，示例成员 Harry 站在显示名的位置上。

## 决定

**问候仍按时段编键；寄语按半小时编键。** `hero.<part>.greeting` 保留原名，现在读作 `Hi {name}，<时段>好！我是小微，…`。`hero.tagline.<HHMM>` 承载它下面那一行，每个半小时一个键，以它开始的本地分钟命名，从 `0000` 到 `2330`。七个时段得以保留，是因为问候在不同时段仍然问不同的事——上午和下午问工作，其余时段提供帮助——也因为时段表正是 08:30 存在的地方。

**每个时段边界都落在半小时上，因此一个定时器同时服务两行。** [`day-parts.ts`](../../../../packages/team/team-local-login/src/client/day-parts.ts) 中的 `halfHourAt` 返回时段、半小时以及距下一个半小时开始的毫秒数；组件为此安排一次定时，而问候不可能在其他任何时刻改变。`HalfHour` 是覆盖二十四个两位数小时的模板类型 `${Hour}${'00' | '30'}`，因此 `t` 拒绝一个不存在的半小时的寄语键，也拒绝一个词典里缺少寄语的半小时。

**文案就是产品的表，投影过来。** 中文词典逐行就是那张表，`{name}` 站在 Harry 的位置上。英文文案与此前一样是为英文读者写的；助手的名字写作 `Xiaowei`，想要另一种写法的英文部署在自己的词典里写出来即可。

## 考虑过的替代方案

**按时段加序号编键，如 `hero.afternoon.tagline.3`。** 拒绝：表是平的，文案编辑看到的是半小时，而时段内的序号对这一行何时显示什么也没说。`HHMM` 这个名字就是钟面上的时间。

**四十八个时段。** 拒绝：问候只有七句，而不是四十八句，而时段是由它所说的那句话定义的。拆分时段会让每句问候在两本词典里重复多达十三次。

**每分钟轮询时钟。** 出于此前那篇笔记给出的理由拒绝：文案变在已知的分钟上，而一次到下一个半小时的定时恰好就是这次变化所需要的那次唤醒。

**每个时段保留一句寄语，多出来的句子随机轮换。** 拒绝：表把每句话绑在它的钟点上——23:30 说的是子夜临近——而随机抽取会在 18:00 说出这句话。

## 后果

词典每种语言五十九个键：三条入口文案、七句问候、四十八句寄语，以及成员回退名。`satisfies Record<TeamAccountKey, string>` 在文案增删或改名时保证英文相对中文键集是完整的，而缺少一个寄语键会让客户端类型检查在 `HeroGreeting.tsx` 的 `t` 调用处失败。

组件一天醒来四十八次而不是七次；每次唤醒都是空白页上的一次 `setTimeout`。

此前那篇笔记保留它仍然拥有的决定——七个时段、浏览器时钟、跨越、名字把持标题——并就寄语的键和定时器的目标指向这里。

`day-parts.client.spec.ts` 钉住每个时段、一个小时两个半段各自的半小时名称，以及到下一个半小时的等待，包括到午夜的等待。组件测试钉住 08:30 的跨越——问候与寄语一起改变——以及 09:00 的跨越——问候随半小时改变。这些文案都不会到达模型或会话日志，因此没有快照拥有它们。
