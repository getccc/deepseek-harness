# Agent Note：一个能被告知"你太旧了"的 Runner

Status: implemented

[English](2026-08-30-a-runner-that-can-be-told-it-is-too-old.md) | 中文

## 问题

Runner 安装在成员自己的电脑上，并按各自的节奏更新，因此一家公司里永远会同时跑着好几个版本。由此有两个后果，而把版本当成又一个普通字段，两者都得不到解决。

Control Plane 早晚需要停止应答那些太旧、不能再托付某项变更的 Runner。如果那次拒绝与一次普通失败无法区分，Runner 会永远重试，而成员看到的是一个"不工作的产品"，而不是一个"需要更新的产品"。

而 Runner 会替换自己的可执行文件。判定"这个被提供的发行版可以安装"的那个环节，是唯一一处判断错误就等于把这台机器交给发行版制造者的地方。

## 决策

**协议版本在任何其他东西读取请求体之前就被判定。** 每一个面向 Runner 的端点先检查版本并回答 **426**，同时附上受支持范围，于是太旧的 Runner 学到的正是这件事，而不是某个含义在它脚下变过的字段所引发的下游抱怨。范围随拒绝一同送达，因为 Runner 无法通过一个对方刚说"我不讲"的协议去索要它。

`too-new` 是与 `too-old` 不同的回答：它意味着需要更新的是这个 Control Plane，说清这一点能让管理员不去折腾成员的安装。

**这与绑定比较是两项不同的检查。** 接缝依然会拒绝 `protocolVersion` 与 Transaction 开启时不同的兑换，并依然把那称作 `binding-mismatch`。"我们究竟讲不讲这个"和"这是不是该 Transaction 绑定时的那个版本"是两项性质，把它们混为一谈会让 Runner 无法区分一次升级和一次被篡改的 Callback。

**更新判定先验签，且针对规范字节。** 此后的每一项检查读到的都是发行密钥背书过的值，而不是文档自称的值。规范编码固定了字段顺序并对产物排序，因此同一个发行版无论产物以何种顺序排列都签出相同结果，而一个重排了字段的文档也无法把另一份签名冒充为有效。

**版本按数字比较并忽略预发布标记**，因为 harness 自身的版本里就带着它们，而一次更新判定不能取决于它们如何排序。不以数字开头的字符串会被拒绝，而不是被猜测。

**`minimumFrom` 让升级路径可被表达。** 一个无法叠加在更旧构建之上的发行版会明说这一点，低于它的 Runner 会先安装一个中间发行版，而不是在已经替换掉自己之后才发现问题。

**后台服务以成员身份运行。** 一个 launchd agent、一个 systemd user 单元、一个 Windows 计划任务——绝不是 daemon、system 单元或服务。Runner 以成员自己的权限执行成员自己的工作，而每个平台的提权形态都会让它以别的身份运行。三者都会在崩溃后重启并带十秒下限，因此启动不起来的 Runner 会显式失败，而不是对着它的服务管理器空转。

## 曾考虑的替代方案

**用 400 拒绝过旧的协议。** 已否决：400 说的是请求格式有误，而据此行动的 Runner 会继续发送同一个格式正确的请求。426 说的是请求已被理解、并因客户端本身而被拒绝，那正是一次更新能修好的那种拒绝。

**把"太旧"并入既有的 binding-mismatch 原因。** 已否决：Callback 被篡改的成员和应用过期的成员需要的是不同的东西，而一个词无法把它们区分开。

**对清单的 JSON 文本签名。** 已否决：那会让签名依赖空白与键顺序，于是一份重新序列化、含义完全相同的清单会验签失败，而生产方与验证方必须就一个序列化器达成一致，而不是就一个格式达成一致。

**用 semver 库比较版本。** 暂时否决：这次判定唯一需要的排序是数字分量上的，而库额外提供的预发布排序，恰恰是不能影响它的那部分。

**从本包安装服务定义。** 已否决：往 `~/Library/LaunchAgents` 或计划任务里写入需要安装程序拥有、而库不拥有的权限与平台知识。属于产品决定的部分——以哪个账户运行、是否重启、多快重启——在这里陈述一次，而不是在三个安装程序里陈述三次。

## 后果

**本仓库不产出带签名的平台安装包。** `.pkg`、`.msi` 或 `.deb` 需要不属于本次构建的代码签名证书与平台工具链，因此交付的是那些安装程序所执行的判定，而不是安装程序本身。打包工作仍然未完成，README 明说这一点，而不是暗示已经覆盖。

这里也没有任何东西下载或应用产物。清单指名了摘要和大小；把字节对照它们检查、以及替换可执行文件，属于安装程序。

只有一把发行密钥，由调用方传入。轮换意味着一个信任多于一把密钥的目标，那是一项设计而不是多加一个参数，而以后补上它不会改变这里所做的任何判定。
