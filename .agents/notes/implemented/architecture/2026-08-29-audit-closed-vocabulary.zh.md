# Agent Note：一条审计记录没有地方放一句话

Status: implemented

[English](2026-08-29-audit-closed-vocabulary.md) | 中文

## 问题

Team Edition 会审计登录、设备绑定、Credential 轮换、策略变更，以及——将来——每一次公司模型调用和知识库查询。围绕这一切的产品承诺是：成员的工作留在成员自己的电脑上。不含 Prompt、不含代码、不含路径、不含 Diff、不含 Tool Arguments、不含查询文本。

这样一条承诺通常靠一份文档里的规定和一位记得它的评审者来兑现。它会以最寻常的方式失效：某人因为一个 Bug 难以诊断而加了一个 `details` 列，某人把上游错误消息放了进去，而那条消息引用了请求本身。没有任何东西会宣告：这份审计现在装上了它承诺不装的东西。

底下还有第二个问题。一份审计只有在无法被改写时才值得读，而"服务恰好不提供更新方法"的存储，和"存储会拒绝更新"的存储，并不是一回事。

## 决策

**一条记录没有自由文本字段，而它确实拥有的那些字段装不下散文。** 列是固定的。动作和拒绝原因是封闭词表。每一个由调用方提供的字符串——`resourceId`、`deviceId`、`correlationId`，以及任何 `ref` 类 Metadata——都必须匹配 `AUDIT_TOKEN`：最多 64 个字符，取自字母、数字和 `. _ : @ -`。真正起作用的是被排除的那些字符：不含空格排除了散文，不含斜杠排除了路径和 URL，长度上限排除了同时挺过这两关的东西。

因此一次拒绝携带的是 `AUDIT_REASONS` 中的一个词，而不是一条消息。那正是读者最想要一句话的地方，也正是一句话最可能引用请求本身的地方。

**Metadata 是封闭目录，而且封闭了两层。** `METADATA_KEYS` 为每个 Key 注册一种类型——`count`、成员完整列出的 `label`，或 `ref`——每个动作再声明它携带其中哪些 Key。注册表明某个子系统会记录这项事实；声明表明哪一项操作可以记录。少了后半截，任何 Key 都能搭上任何操作的便车，而"受限 Metadata"就只意味着这些 Key 曾在某处被命名过。

**调用方指名动作，从不指名资源类型。** 类型来自 `AUDIT_ACTIONS`，因此一条记录无法把角色变更描述成设备事件，存储里也没有一份需要去约束的反规范化副本。

**Schema 把每一条规则都再陈述一遍。** SQLite 后端把两份目录播种进表并用外键指向它们，从 Definition 导出的数组渲染出 Outcome 与 Reason 的 `CHECK` 列表，并把 Token 规则作为 `NOT GLOB` 检查在每一个文本列上重复一次。四个触发器在两张表上中止 `UPDATE` 和 `DELETE`。一个直接打开数据库的调用方会被存储拒绝，这正是让隐私主张成为存储的属性、而不是其调用方的习惯的原因。它的测试特意开第二条连接写裸 SQL，也正是为此：一个只走服务的测试，面对一份毫无约束的 Schema 也照样会通过。

## 曾考虑的替代方案

**一个 JSON Metadata 列。** 已否决：那是一个披着结构化名字的自由文本字段。调用方传什么就原样存下什么，而数据库能表达的任何约束都拦不住它。

**一个自由形式的 `message` 或 `details` 列，并在文档中规定只放元数据。** 出于问题一节所述的理由否决。这条规则的文档版本，其寿命恰好等到下一个需要调试点什么的人为止。

**只在服务里校验。** 已否决：存储是一个持久化边界，而将来会向它写入的那些操作——管理 API、RPC 网关——是跨线到达的，那里 TypeScript 的保证早已结束。

**在访问控制和账户存储内部写审计。** 已否决：`createRole` 没有主体、没有设备、没有关联标识，因此写在那里的记录只能凭空编造出正是让它成为证据的那些字段。审计由知道谁动了手的那次操作写入，也就是管理 API，而不是一个存储原语。

**一种布尔 Metadata 类型。** 已推迟：没有调用方需要它，而没有 Key 的种类是一个没人看着的洞。

## 后果

每一项新的受审计能力都会新增一条 `(action, resourceType, metadata)` 条目，它携带的任何新事实则新增一个带种类的 Metadata Key。两者都通过 Schema 的播种在下一次启动时到达已有数据库，不需要提升 Schema 版本。退役一条条目会让它的目录行留在原地，好让已存事件保住外键；阻止它被再次记录的是代码目录，而读取时会丢弃当前构建已退役的 Metadata Key，而不是抛出一个没有任何消费方声明的值。

**保留期无法通过删除行来实现。** 触发器是刻意拒绝它的。一个保留窗口将需要一条有文档的特权路径，例如在一次 Schema 迁移中删除某个触发器。

**一条记录不与它所描述的变更一同提交。** 在 SQLite 这项偏离之下，每个子系统各自拥有自己的数据库，因此一次操作与它的审计记录各自提交——策略修订号早已跨越同一道裂缝，因为那个计数器住在账户存储里。方案中的单一数据库假设才是能弥合它的东西，而把 Control Plane 的各个存储合并到一条连接上，正是能买到它的那次改动。
