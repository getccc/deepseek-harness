# Agent Note：绑定证明三件事，三者缺一即拒绝

Status: implemented

[English](2026-08-29-device-binding-proves-possession.md) | 中文

## 问题

成员在浏览器里登录公司站点，而他们自己电脑上的一个后台 Runner 必须最终握有一份凭据。浏览器和 Runner 是两个信任程度不同的程序：浏览器有一个已认证的会话，却无法证明它正坐在哪台电脑前；Runner 在正确的电脑上，却无法证明是哪个成员拥有它。

最朴素的桥梁是让站点把一个 Token 递给 Runner。那只确立了"这台机器上的某个东西能连上 loopback 端口"，而任何本地程序都能。它既不回答"哪个成员"，也不回答"哪台电脑"——它回答的是"哪个端口"。

## 决策

**绑定分别证明三件事，三者缺一即拒绝。** 有成员批准了它，来自一个已认证的 Control Plane 会话，组织与账户正是从那里来的。他们批准的是*这一台*电脑，通过在本地页面与 Control Plane 页面之间比对配对码与公钥摘要。而这台电脑握有他们比对过的那把钥匙，通过在兑换时用私钥签名。

每一件都覆盖另外两件无法覆盖的部分。少了第三件，成员批准的是一份任何程序都能拿给他们看的摘要；少了第二件，他们批准的是一台自己从未识别过的电脑；少了第一件，结果与任何账户都无关。

**Transaction 在被确认之前不携带账户。** `start` 接受一个公钥和一个 PKCE Challenge，返回一个 Transaction ID 和一个配对码，因此在没有会话的情况下打开 Transaction 的调用方，只能学到它自己已经提供的东西。Schema 陈述了这一点：一条 `CHECK` 把 pending 状态与为空的 `org_id` 绑在一起，两半无法各自漂移。

**被签的字节同时指名 Transaction 和 Code。** 从一次兑换中截获的签名对另一次毫无用处。Code 本身不在被签串里——里面只有它的哈希——否则一份泄露的签名会顺带携带造出它的那个 Code。

**被重放的 Refresh Token 会吊销它的整个 Family。** 要么 Token 泄露了，要么 Runner 弄丢了它的记录，而这次交换无法区分两者，因此都用同一种方式回答：让该 Family 中的每一份凭据失效。这刻意连同正当持有者一起惩罚：另一种做法——忽略这次重放——会让一个被窃 Token 在整个 Family 的生命周期内一直可用。

**撤销一台设备会在同一次操作中吊销它曾经开启的每一个 Family。** 读取方只检查 Family，因此一台被撤销却留着活 Family 的设备，依然能拿到 Token。

**Access Token 不携带授权。** Token 指名一个组织、一个账户、一台设备。角色与授权按请求、对照当前策略修订号读取，因此角色变更立即生效，不必等某个 Token 过期。

## 曾考虑的替代方案

**带 Claims 的 JWT Access Token。** 已推迟：每一个会去验证它的一方都能连到数据库，因此一个签名 Token 今天什么也买不到，却要付出一把签名密钥、一套轮换方案，以及第二个可能让授权事实变陈旧的地方。当出现一个连不到该存储的验证方时，它才值得。

**信任 loopback 端口。** 按问题一节所述否决：连上一个 loopback 端口只证明本地性，而每一个本地程序都具备它。

**一个长到足以独自抵抗猜测的配对码。** 已否决：人要在两块屏幕之间比对它，而长度的代价是误读。它并不承担安全性——那由已认证的确认会话承担——因此它转而为眼睛优化：不含元音，于是拼不出让眼睛自动补全的单词；也不含 `0`、`O`、`1`、`I`、`L` 中的任何一个。

**在读取方保留一个设备状态检查。** 已移除：撤销一台设备会在同一次调用中吊销它的各个 Family，因此一个活着的 Family 必定属于一台活着的设备。该检查永远不会触发，而不可达的防御是一项没有任何东西去测试的主张。改为直接断言这条关系，并覆盖同一把钥匙更早那次绑定。

## 后果

`codeTtlMs` 可向下配置，并由构建封顶在 60 秒。它对"调短"是一个部署旋钮，对"调长"是一条安全不变量，因为 Code 恰好只走一次重定向。

过期 Transaction 与已消费 Token 从不清理。两者都被保留以便重放可被检出；删掉一个已消费的行，会让一次重放与一个从未存在过的 Token 无法区分。保留期处理需要它自己的设计。

这里的任何东西都不保护 Runner 自己的进程。与 Runner 共享同一 Cordis 进程的插件可以读到设备私钥，而短有效期与撤销缩小窗口，并不隔离它。威胁模型在第一版接受这一点，补偿手段——私有插件准入审核、Artifact 签名、默认禁用未知公共插件——在别处。

在 SQLite 这项偏离之下，本存储是它自己的数据库。这里没有任何东西写审计记录，因为将来会调用它的那些操作——Control Plane 的 HTTP 面、管理 API——知道设备、关联标识和 Browser Session，而本存储只是记录它们。
