# Agent Note：登录不等于被允许，而一次写入需要三样齐全

Status: implemented

[English](2026-08-30-signing-in-is-not-being-allowed.md) | 中文

## 问题

Control Plane 需要页面：一个用来登录的地方、一个让成员确认那台请求连接的电脑的地方，以及一个让管理员管理成员、角色和设备的地方。最诱人的形态是每个小型管理面板都有的那一种——登录之后，面板就是你的了。

那个形态把两个问题压成了一个。"这是哪位成员？"和"这位成员可以做这件事吗？"由不同的子系统回答，而一个把"成功登录"当作"许可"的面板，没有地方安放第二个答案。它同时让审计无法说出是谁做了什么，因为知道主体的正是这个面板，而它下面的那些存储并不知道。

底下还有一个更窄的问题。一次携带会话 Cookie 的表单提交，并不是"成员提交了这个表单"的证据：浏览器会把 Cookie 附加到由另一个站点引发的请求上。

## 决策

**登录对任何成员都会成功；此后每一个页面和每一次操作都会单独询问访问控制。** 一个没有任何授权的成员登录之后依然什么也做不了，包括读取成员列表。正是这一点给了第二个问题一个可以被回答的地方，而它由一个"认证成功却被拒绝每一次读取和每一次写入"的成员来验证。

**每一次写入都需要三样齐全。** 会话说明是谁在问。同源浏览器元数据说明请求来自这些页面：普通 `Origin` 必须指名与请求相同的 authority，而携带 `Origin: null` 的不透明上下文必须同时携带由浏览器控制的 `Sec-Fetch-Site: same-origin`。由会话导出的 CSRF Token——一个不同于 Cookie 的值——说明这个表单是本会话渲染出来的。缺少任何证明都是拒绝。

导出而不是存储 CSRF Token，意味着没有第二份记录需要与会话保持同步；而它不是 Cookie 自身的值，因此单是携带 Cookie 并不足够。

**Team Shell 负责写审计记录**，因为它才是知道主体的那一方。这正是审计接缝当初为之而建、并刻意在没有它的情况下先行交付的那个消费方：一个创建角色的存储没有主体、没有设备、也没有可记录的关联标识。

**一次失败的登录不记录任何账户。** 究竟是"查无此人"、"密码错误"还是"已锁定"，正是攻击者想要的，因此页面对三者回答同一条消息，记录也不指名任何账户。记录账户会把审计变成一份"哪些登录名存在"的清单。

**会话 Cookie 是 `SameSite=Lax`。** 成员是从自己 Runner 所服务的配对页上的链接到达确认页的，那是一次跨站顶层导航。`Strict` 会在那里扣下会话，并毫无理由地要求他们重新登录。这与 Runner 一侧的决定互为镜像：那边的本地 Cookie 保持 `Strict`，而 Callback 以一个自我导航的页面而不是重定向来回答。

**停用一个成员本身就是完整的一次行动。** 会话经由账户解析，而被停用的账户不持有会话。没有任何东西需要记着同时结束他们的会话，而任何忘记了的东西也不可能留下一个仍然登录着的被停用成员。

## 曾考虑的替代方案

**一个携带成员身份的签名会话 Cookie。** 已否决：那样撤销就意味着等待签名过期，而停用一个成员在那之前不会生效。一个不透明 Token 加上存储中的哈希，让结束会话成为即时的，也让账户状态成为解析会话的一部分。

**把 CSRF Token 存在会话旁边。** 已否决：那是第二份必须与第一份保持同步的记录，而它的值本就是第一份的一个纯函数。

**只凭 CSRF Token 拒绝写入，不检查浏览器来源元数据。** 已否决：它们拒绝的是不同的东西。Token 检查拒绝一个被伪造的表单；浏览器元数据拒绝一个来自"从未渲染过任何表单"的页面的请求，包括那种猜测"大概不需要 Token"的请求。

**让存储故障以拒绝文案回答 400。** 在覆盖率门禁把它暴露出来之后否决：那个兜底分支只有在失败不携带拒绝词时才可达，而它告诉成员他们的请求无法识别。存储故障现在回答 500 并记录 `outcome: 'error'`，因为一条"说成员被拒绝了而其实并没有"的记录，比没有记录更糟。

**相信渲染出的表单会提供每一个字段。** 在一个测试显示空登录名一路到达存储并被存下之后否决。每一个操作现在都指名它无法缺少的字段，缺少其一的表单在任何东西被写入之前就被拒绝。

## 后果

账户存储获得了浏览器会话：`createBrowserSession`、`resolveBrowserSession` 和 `revokeBrowserSession`，`SCHEMA_VERSION` 提升到 2。该表是增量式的，且每条语句都是 `CREATE ... IF NOT EXISTS`，因此已有数据库会在下一次打开时获得它——这也纠正了一份 README，它曾声称第一次 schema 变更需要一条它其实并不需要的迁移路径。

`revokeUserBrowserSessions` 写了又删：停用一个成员已经通过状态检查结束了他们的会话，因此那次显式调用改变不了任何结果，而一个没有调用方的接缝方法，是一个没有人负责让它保持正确的表面。

授权编辑没有页面。角色可以被创建和绑定，但一个角色携带什么是通过访问控制服务设置的。今天需要修改授权的管理员在那里做，而为它准备的页面需要它自己的设计——一个角色的授权，是本产品中最容易因一个表单而出大错的东西。
