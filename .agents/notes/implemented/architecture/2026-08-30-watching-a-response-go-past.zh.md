# Agent Note：看着一个响应过去

Status: implemented

[English](2026-08-30-watching-a-response-go-past.md) | 中文

## 问题

网关决定一次公司模型调用**可以**花多少；Provider 前面的那个端点，才是它得知**实际**花了多少的地方。那是同一个请求的两侧，而第二侧多出两条第一侧没有的约束。

模型响应很长，而且常常是流式的。Control Plane 同时为每位成员服务一份，因此一个把响应读进内存去检查的端点，会为每个并发请求留住一整份 completion——而且还会破坏流式，而流式正是让 Agent 显得有响应的那件事。

同时，结算规则在 Provider 的 Usage 可得时需要它。那个数字就在响应**内部**：非流式回答在响应体里，流式回答在最后几帧之一里。读到它，意味着在字节同时被转发给成员的过程中看着它们。

## 决策

**一个扫描器看着响应过去，只保留一行和一个 usage 对象。** 两种响应形态都经由它：非流式响应体是一份 JSON 文档，而流是一串 `data:` 帧、其最后几帧携带 usage。别的一概不留，响应在每个 chunk 到达时就写给成员。

**最新的 usage 胜出。** 流在最后几帧报告 usage，而更早那帧携带的部分计数，不该压过最后的定论。

**半份报告不是报告。** 一个有输入计数而没有输出计数的 usage 对象会被拒绝而不是被补全，因为在一个真实输入旁边计上一个凭空的输出，是一个披着 Provider 权威外衣的估算。

**每种结果如何结算**，遵循已冻结的规则：

| 结果 | 结算 |
|---|---|
| Provider 报告了 Usage | `reported`，无论状态如何——那些 Token 已经生成 |
| 状态 ≥ 400 且没有 Usage | `released`——Provider 表示它没有接受该请求 |
| 成功但没有 Usage 字段 | 按上限 `estimated`——它可能仍然产出了 Token |
| 完全没有响应 | 按上限 `estimated`——没有响应不是拒绝的证据 |

一个中途失败却仍然报告了 Usage 的 Provider，按它所报告的计费：那些 Token 是它生成的，状态并不能把它们抹掉。

**结算失败不是成员的问题。** 如果结算抛错，成员已经收到的响应保持有效，由 Reconciler 稍后关闭那笔预留。在那里抛错，会用一个关于记账的错误替换掉一个已经可用的答案。

**凭据只为一次调用而存在。** 它在请求发生的那一刻被解析，且不被写到任何地方——不写进计划、不写进目录、不写进日志。一条指名了没人配置过的引用、或者根本不是凭据引用的目录记录，回答 500 且不计费：那是部署的问题，不是成员的。

**对每一个坏 Token 只有一种回答。** 未知、过期、设备已被撤销，一律 401，因为究竟是哪一种，恰恰是持有陈旧 Token 的攻击者想要知道的。

## 曾考虑的替代方案

**把响应缓冲下来解析。** 在两点上都被否决：每个并发请求的内存开销，以及流式的丧失——而流式正是"会打字的 Agent"与"会停顿的 Agent"之间的区别。

**再发一次请求向 Provider 索取 Usage。** 已否决：那会让请求数翻倍，而且并非每个 Provider 都提供按请求的 Usage 查询。那个数字本来就在响应里。

**按 Runner 报告的"我收到了什么"来结算。** 已否决：Runner 正是被计费的一方，而一份信任它的结算，就是一份它可以调低的结算。

**把任何非 2xx 都当作释放。** 已否决：一个生成了 Token 然后失败的 Provider 报告了那些 Token，而释放会让一次部分失败变成免费。状态只决定"Provider 什么也没报告"的那种情况。

**除时间之外再按字节给响应设上限。** 已推迟：一个切断了合法长 completion 的字节上限，比它所防的那种失败更糟，而超时已经限住了永不停止的 Provider。

## 后果

端点不写审计记录，而设计要求对每一次公司模型的允许与拒绝各写一条。它已经持有关联标识与设备；补上那条记录是一次本次未做的小改动，它被写进包的"已知限制"，而不是被含糊带过。

`upstreamTimeoutMs` 应当高于部署所预期的最长一次完成。被它切断的请求会按上限计费，因为一个停止应答的 Provider 可能仍然生成过 Token——所以把它设得过低，等于为成员确实收到了一部分的工作向他们多收费。

"不记录请求体"与"这个部署无法记录请求体"不是一回事。端点不写关于请求体的任何东西，但它不配置周围的进程，而一个在别处开启了请求日志的部署会让这一点失效。设计中的隐私说明区分"不持久化"与"请求处理期间不可见"，而这里正是那个区别真实成立的接缝。
