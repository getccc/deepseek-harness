# Agent Note: Control Plane 策略治理常驻 Runner

Status: implemented

[English](2026-08-31-control-plane-policy-governs-the-resident-runner.md) | 中文

## 问题

Team Edition 把服务器部署的管理应用与每位成员电脑上的 Runner 分开。把 Runner 安装为桌面应用不能让本机进程变成第二个策略权威，而远程策略变更必须在 Runner 后台常驻时仍然生效。密码替换、模型可见性、设备清单与进程常驻需要一套一致的归属模型。

## 决定

**Control Plane 拥有账户与资源策略；Runner 拥有本机执行与凭据保管。** 管理员在端口 `3095` 创建账户、替换密码、组合角色、绑定精确模型资源并撤销设备。成员在本机端口 `3090` 认证；Runner 通过 TLS 把密码发送给已配置的 Control Plane、持有由此得到的设备凭据，并使用当前访问 token 向 Control Plane 请求模型目录。它不会把授权策略复制到本机数据库。

**替换密码会撤销进入该账户的每一条现有路径。** 管理写入先存储新密码，再撤销全部 Control Plane 浏览器会话以及该账户拥有的所有设备凭据族。因此，常驻 Runner 会失去刷新与模型访问能力，并让成员返回本机登录。这也适用于管理员自己的账户；相应响应会让当前管理 cookie 过期。

**模型是受治理资源，而不只是目录行。** 每个目录模型都有一个托管资源 id。角色编辑器选择精确模型资源，并用所选 id 的精确授权替换该角色的模型发现与调用授权。Runner 发现操作评估当前设备主体，并且只返回它可发现的活跃模型；调用操作还会独立要求匹配的调用授权。

**设备清单展示在账户所有者下面。** 管理 API 保留设备清单与撤销操作，而浏览器应用把每位成员的设备渲染在可展开的成员行中。移除独立导航页面不会创建第二种归属关系，也不会改变鉴权检查。

**Electron 拥有桌面常驻，而不拥有授权。** 桌面外壳启动随附的 Team profile，在窗口关闭时隐藏、从托盘保持可用、注册用户级登录项以便后台启动，并在 Runner 意外退出十秒后重启。明确退出会终止两个进程。一份企业构建携带一个经过验证的 Control Plane 源，但不携带账户或提供方秘密。

**桌面平台集合是 Windows x64 与 Apple 芯片 macOS。** macOS 打包器只生成 `arm64` DMG 产物。Intel 与 Universal 构建直接缺席，而不是把未经测试的变体展示为受支持平台。

## 曾考虑的替代方案

**密码替换后保持设备 token 有效。** 已否决，因为被盗的设备凭据会挺过账户所有者的恢复操作。要求每台设备重新认证，让密码替换成为没有歧义的账户级恢复边界。

**在每个 Runner 中缓存角色到模型的选择。** 已否决，因为后台常驻会产生陈旧的授权窗口以及一套撤销协议。使用当前访问 token 进行发现，让 Control Plane 的普通访问决策在每次刷新时都保持权威。

**把 Runner 作为特权系统服务运行。** 已否决，因为本机工具与工作空间属于操作系统用户。用户级登录项在不改变工作执行身份或权限的情况下提供后台可用性。

**发布一份 Universal macOS 安装程序。** 已否决，因为不需要 Intel 支持，而 Universal 产物会为不受支持的架构增加构建、签名、下载与验证工作。

## 结果

密码替换有意造成中断：每个浏览器与每台电脑都要重新登录，包括执行自助重置的管理员。设备行仍可用于清单查看，但它们的凭据族会立即撤销。

模型展示与模型调用在同一资源 id 上使用两个明确动作。一次角色选择会同时写入两者，使普通产品流程不会展示不可用模型，而网关仍然独立检查调用权限。

常驻外壳必须保持为普通成员进程。安装程序无需管理员权限即可启用登录启动，支持人员也可以区分关闭窗口与明确退出 Runner。

企业分发会分别生成 Windows x64 与 macOS arm64 产物，并把部署的非秘密 Control Plane 源写入各个构建。更改该源需要重新构建。
